# 0.7.2 design note — the grading-spine fix pack

Five candidates from the GCC field deployment's dogfooding (lessons L27, L34,
L51, L54, L55, L58, L61; sessions 0070/0079/0082/0083), plus one feasibility
assessment. Each candidate below records ship-or-defer with the design chosen.

Invariants held throughout, test-pinned:

- **Terminal verdicts are immutable.** Nothing in this release re-grades a
  `verified`/`contradicted`/graded-terminal record.
- **Never-block.** No new context line or escalation blocks a stop that passed
  under 0.7.1. Two changes *relax* gates (grace defers a contradicted verdict;
  interim un-arms the stalled block) — the composed pair carries its own
  regression test (lesson L25).
- **Additive schema.** Every new field is optional; 0.7.1-and-earlier records
  load unchanged.

## 1. Terminated-ungraded verdict loss — SHIPPED (diagnosis + two fixes)

**Diagnosis.** The spine does not "lose" verdicts to stop-event ordering. On
every path where a terminal transition lands on a dispatch *with runnable
checks*, the gate grades first (`subagent_stop` grades before every close it
writes; the abandonment and no-report terminals both carry verdict-or-reason).
The field's terminated-ungraded rows (sessions 0070/0082, MCC's same class)
are the **no-contract shape**: a named spawn's agent_type is the NAME, no
intent sidecar matches (L34/L51), the capture is manifest-less at a tier the
repo spec leaves empty — so at stop time there is *nothing runnable*, and the
gate closes the dispatch ungraded by design ("an absent grade is not a passing
grade" forbids inventing a verdict). Even `dispatch verify --terminal` then
returns "no runnable check at this tier", because a manifest could not be
attached post-hoc. Verdict loss is therefore a contract-attach failure, cured
at three layers:

- **Capture layer:** candidates 4b and 5 (below) stop the contract from
  detaching in the first place.
- **Visibility layer:** the ungraded close is now loud *in-band*, not just
  stderr. When the SubagentStop gate closes a reported dispatch ungraded
  (nothing runnable, or every check retired), the stop now returns
  never-suppressed `additionalContext` telling the dispatcher the dispatch
  closed UNGRADED and why — including, when the record carries an intent-miss
  stamp, which unconsumed sidecars existed at spawn and the match-key rule.
  Context, never a block: the same channel the abandonment and no-report
  terminals already use. The board face (`ungraded` verdict column, footer
  line, bridge-stop stderr) was already honest; the gap was the moment of
  closure reaching the dispatcher's transcript.
- **Recovery layer:** `dispatch verify --manifest <file>` — the sanctioned
  out-of-band grade for a record that never got its contract. Operator-only
  (stamped `cli-verify`), legal ONLY when the dispatch carries no verdict
  (terminal-ungraded with `--terminal`, or stuck non-terminal) AND its own
  manifest declares no checks (a dispatch that carries a contract is graded
  against it, never a substitute). The supplied manifest never overwrites the
  record: `dispatch.json` keeps the manifest that was in force at spawn; the
  grade writes `post-hoc-manifest.json` beside it and stamps the verdict
  transition with `post_hoc_manifest_sha256` + the file name, so the trail
  says exactly what this verdict was graded against and that the contract
  arrived after the fact. Re-grading an existing verdict remains refused on
  every path.

## 2. Check-grace for long in-dispatch builds (L58) — SHIPPED

**Design chosen: declared grace, blocking-not-grading.** "Grade contradicted
only at the FINAL stop" is not implementable from the hook's seat — a
SubagentStop payload does not say whether the agent is done or interim, so
"final" is unknowable. Instead the manifest may declare `"grace_stops": N`
(int >= 1; read tolerantly — a malformed value is ignored with a stderr note,
never nukes the manifest). Under an **armed** gate, the first N stops whose
blocking checks fail are *blocked without a verdict*: the block text names the
grace ("grace stop N of M consumed — no verdict recorded; finish the artifact
and stop again"), the block is persisted with a `grace: true` meta flag, the
dispatch stays at `reported`, and the abandonment ladder neither strikes nor
counts. Once grace is exhausted, failures grade `contradicted` exactly as
before, with the full 3-strike ladder — total wedge bound = `grace_stops + 3`
blocks, still finite (the 0.7.0 no-unbounded-loop rule).

Edges, decided and documented:

- Grace is grace-before-verdict, never verdict-rewrite: a `contradicted`
  recorded after grace exhausts is as permanent as ever.
- A **disarmed** (advisory) tier ignores grace: that branch must never block,
  and introducing a grace block there would violate never-block. A long build
  at a disarmed coordinator tier still grades `advisory` at its first failing
  stop — unchanged 0.7.1 behavior, named here so nobody assumes otherwise.
- `dispatch verify` ignores grace: the operator's out-of-band grade is by
  definition the final look.
- To keep the claim fresh across grace retries, `reported -> reported` is now
  a legal transition: a re-report overwrites `report.json` and appends to
  `reports/NNN.json` exactly like the contradicted-retry path, so the final
  stop's claim is the one on file (previously a pin-drift or grace retry kept
  the stale first body). Every body is still kept; telemetry's retry_count
  counts re-reports as it already counted them.

## 3. Interim-report state — SHIPPED

A living report filed mid-flight (`dispatch report` from the CLI, no stop
event) left the dispatch at `reported`, which the bridge sweep reads as
"reported but never terminated" and **blocks** on — the verify-or-close gate
armed before the lane was done (session 0083 dogfood finding).

**Design: a flag on the report event, not a new state.** `dispatch report
--interim` records the same reported transition carrying `"interim": true`.
The bridge sweep classifies a dispatch whose *last* report is interim into a
fourth bucket: rendered as `- [interim report] <id>: ... verify-or-close not
armed until a final report or terminal close`, context, never a block. The
stale escalation still covers it: silent past `stale_dispatch_minutes` it
renders `[STALE interim report]` with the same check-the-agent-now wording —
an interim lane that dies is exactly the L55 shape and must not hide behind
its flag. A later plain (final) report, or any verdict/terminal transition,
re-arms the ordinary gating. Scope deliberately bounded: no hook behavior
changes, no workflow redesign; `verified`/`advisory`-unclosed rows still read
stalled and still block.

Self-service note: an agent could in principle mark its own CLI report
interim to dodge the stalled block — but it cannot dodge the stale
escalation, the `ungraded` accounting, or the board face (`reported
(interim)`), so the flag hides nothing terminal. Accepted.

## 4. Intent-sidecar hygiene — SHIPPED (both halves)

**(a) Staleness.** Unconsumed sidecars linger and attach to the next
same-named spawn, misattributing a prompt. Two additive surfaces, no
consume-side TTL (a TTL that silently refuses a slow operator's sidecar would
re-create the manifest-less capture this whole release fights):

- The fleet board footer lists unconsumed intent sidecars with their age
  (`fleet --format json` carries `unconsumed_intents`), naming the risk.
- `dispatch sweep --intents` extends the existing sweep: sidecars older than
  `--older-than` are deleted (listed under `--dry-run` first), reported
  separately from swept dispatches.

**(b) The fork.** `dispatch new --agent-name X` + a real spawn produced TWO
records: the CLI record (joinable only at SubagentStop) and the start-hook's
duplicate capture (2 forked pairs in session 0083). The SubagentStart capture
now **joins** instead of minting: among open dispatches with an exact session
match, `capture == "cli"`, matching `agent.agent_type`, and no agent_id yet,
a unique candidate adopts the spawn's agent_id at start (same `_adopt_agent`
audit transition the stop-join writes) and no new record is created. Two or
more candidates is not a guess the hook gets to make — it captures normally
with a stderr note naming them (the stop-side join rule, mirrored). A
matching intent sidecar is left unconsumed when a CLI record joins (the CLI
record already carries the contract), with a stderr warning so it gets swept
rather than silently eaten by a later spawn. Intent-first (`dispatch intent`)
remains the first-class path; the join is for dispatchers who chose
`dispatch new --agent-name`.

## 5. Name-mismatch warn (L34/L51) — SHIPPED

When a spawn matches no sidecar while unconsumed sidecars exist, the capture
now records `intent_miss` on the dispatch — the sidecar filenames present at
spawn — and the stderr line states the match-key rule. The stamp is what lets
the *stop* warn in-band hours later: the ungraded-close context (candidate 1)
names the sidecars that sat unconsumed and says "named spawns report the NAME
as agent_type; register the intent with `--agent <spawn-name>` or `--role
<spawn-name>`". `dispatch intent --agent/--role` help text now states the
rule at authoring time. The board's `lane?` face (defaulted, no intent
matched) already marks these rows; the footer's unconsumed-sidecar line (4a)
is the standing signal.

## L61 feasibility — ASSESSED, NOT BUILT (formally bridge/harness-side)

Question: can the stop/ledger context carry a signal about the reporting
agent's undrained inbox or in-flight background work?

**No, not from the hooks' seat.** Verified against the hook payloads this
codebase actually receives (`hookgate.py` module docstring, checked against
the Claude Code hooks contract): SubagentStop carries `{session_id,
transcript_path, cwd, hook_event_name, agent_id, agent_type,
last_assistant_message}` — no mailbox state, no queued-message count, no
background-task registry. The harness's inter-agent mailbox and background
shells are harness-internal state with no on-disk surface FleetProof can read
at stop time, and `transcript_path` is a transcript, not a queue. "FleetProof
refuses a done report while the queue is non-empty" would require the harness
to expose queue depth in the stop payload — a harness feature request, not a
hook feature. The mechanization therefore formally stays **bridge/harness
side**: the bridge's drain-before-report rule (GCC L61 guideline) and the
queued harness-side feedback draft are the standing coverage. The one
FleetProof-adjacent mitigation already shipped is 0.7.1's silence-age
escalation (a lane that "completed" then acts on a stale queue shows fresh
ledger events — out of scope for staleness, correctly). Revisit only if the
hooks contract grows a queue-depth field.
